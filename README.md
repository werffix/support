# 🤖 Support Tickets Bot

Масштабируемый Telegram-бот для приёма обращений (тикетов) службы поддержки.
Бот выступает мостом между **пользователями** и **группой поддержки**, используя
нативные **Темы (Forum Topics)** Telegram для организации тикетов.

Каждый пользователь — это отдельная тема в админ-группе. Бот пересылает сообщения
в обе стороны и ведёт учёт обращений в базе данных.

---

## Возможности

### Для пользователя (клиента)
- `/start` — приветствие с кнопкой **«Создать обращение»**.
- После нажатия кнопки бот переходит в состояние ожидания сообщения (FSM).
- Можно отправить **текст, фото, видео, документ, голосовое** и другие медиа.
- Каждому обращению присваивается уникальный номер:
  `✅ Ваше обращение #42 принято. Ожидайте ответа.`
- Если обращение не создано, а пользователь просто пишет сообщение — бот вежливо
  предлагает нажать кнопку **«Создать обращение»** (автосоздание тикетов отключено).
- Встроенная **защита от спама**: лимит сообщений пользователя за окно времени
  и пауза между созданием новых обращений.

### Для поддержки (администраторов)
- При первом сообщении пользователя создаётся новая тема в админ-группе:
  `🟢 #42 | ID: 123456789` (🟢 — тикет открыт).
- Все сообщения пользователя автоматически пересылаются строго в его тему
  через `message_thread_id`.
- Ответ администратора в теме автоматически отправляется пользователю
  (бот отвечает от своего имени).
- Команда `/close` внутри темы:
  - меняет название темы на `🔴 #42 | ID: 123456789`;
  - закрывает тикет в базе данных;
  - уведомляет пользователя: «Ваш тикет закрыт» (с кнопкой создания нового);
  - (опционально, через настройку) удаляет саму тему (`close_forum_topic`).
- Если пользователь пишет снова после закрытия тикета — бот предложит нажать
  кнопку **«Создать обращение»**, и уже после неё создаст новую тему с зелёной иконкой.

## Технологический стек

| Компонент     | Технология                      |
|---------------|---------------------------------|
| Язык          | Python 3.10+                    |
| Фреймворк     | [aiogram](https://docs.aiogram.dev) 3.x |
| База данных   | SQLite через `aiosqlite` (WAL, индексы) |
| Конфигурация  | `.env` через `python-dotenv`    |

> Для лёгкой замены SQLite на PostgreSQL вся логика работы с БД изолирована
> в одном модуле `database/db.py` — достаточно переписать его методы
> под `SQLAlchemy`/`asyncpg`, интерфейс не меняется.

## Локальный запуск

### 1. Установка зависимостей

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. Настройка

```bash
cp .env.example .env
# Отредактируйте .env:
nano .env
```

```
BOT_TOKEN=123456789:AAxxxxxxxxxxxx
ADMIN_GROUP_ID=-1001234567890
DB_PATH=tickets.db
CLOSE_TOPIC_ON_TICKET_CLOSE=false
LOG_LEVEL=INFO

# Защита от спама
ANTISPAM_ENABLED=true
ANTISPAM_MESSAGES=5
ANTISPAM_WINDOW_SECONDS=30
ANTISPAM_TICKET_COOLDOWN_SECONDS=60
```

### 3. Запуск

```bash
python -m bot
```

## Настройка группы поддержки (важно!)

1. Создайте обычную группу в Telegram и **включите в ней «Темы»**
   (Настройки группы → Раздел «Темы»).
2. Добавьте бота в группу и **назначьте администратором** с правом
   *«Управление темами»* (Manage Topics). Без этого права не будут работать
   `create_forum_topic`, `edit_forum_topic` и `close_forum_topic`.
3. Если бот не админ — сообщения не будут приходить, пока не отключён
   режим приватности (BotFather → `/setprivacy` → Disable). С админом
   достаточно прав «Управление темами».
4. Узнать ID группы: отправьте в неё `/id@RawDataBot` и возьмите число
   вида `-100...` в ответе.
5. Впишите этот ID в `ADMIN_GROUP_ID` в `.env`.

## Деплой на сервер (Linux, systemd)

Загрузите проект на сервер и выполните:

```bash
sudo bash deploy/install.sh
```

Скрипт сделает следующее:
- создаст системного пользователя `supportbot`;
- скопирует проект в `/opt/support_bot`;
- создаст `.env` из `.env.example` (заполните токены!);
- создаст `venv` и установит зависимости;
- установит и запустит systemd-сервис `support_bot`.

Полезные команды:

```bash
sudo systemctl status support_bot      # статус
sudo journalctl -u support_bot -f      # логи в реальном времени
sudo systemctl restart support_bot     # перезапуск
sudo nano /opt/support_bot/.env        # правка конфигурации (затем restart)
```

Юнит-файл `deploy/bot.service` запускает бота с `Restart=always`, поэтому
служба переживает падения и перезагрузки сервера.

## Как это работает

```
 Пользователь                  Бот                            Админ-группа
     │  /start                   │                                 │
     │──────────────────────────>│   приветствие + кнопка          │
     │  кнопка «Создать обращение»│                                 │
     │──────────────────────────>│   состояние FSM + приглашение    │
     │  «Помогите с оплатой»      │                                 │
     │──────────────────────────>│   create_forum_topic → тема 🟢  │
     │  «✅ Обращение #1 принято» │   copy_message в тему           │
     │<──────────────────────────│                                 │
     │                           │        ответ администратора     │
     │                           │<────────────────────────────────│
     │  «Ответ: попробуйте…»      │   copy_message пользователю     │
     │<──────────────────────────│                                 │
     │                           │   /close в теме                 │
     │                           │<────────────────────────────────│
     │  «Ваш тикет #1 закрыт»     │   🔴 тема, статус в БД = closed │
     │<──────────────────────────│                                 │
```

**Ключевая идея:** для каждого активного пользователя в базе хранится
`message_thread_id` его темы — по нему бот знает, в какую ветку пересылать
новые сообщения клиента.

## Безопасность и устойчивость

- Вся работа с БД — через асинхронный драйвер `aiosqlite` с WAL-режимом,
  транзакции сериализуются через `asyncio.Lock`.
- Обработка исключений `TelegramAPIError`/`TelegramForbiddenError`:
  заблокированный бота пользователь не роняет консоль администратора —
  событие пишется в лог.
- Бот игнорирует собственные скопированные сообщения (защита от циклов).
- Служебные сообщения тем (`forum_topic_created`) и сообщения не из тикетов игнорируются.
- Логирование: важные события и ошибки выводятся в консоль (`LOG_LEVEL`).

## Защита от спама

Включена по умолчанию и настраивается через `.env`:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `ANTISPAM_ENABLED` | `true` | Вкл/выкл антифлуда |
| `ANTISPAM_MESSAGES` | `5` | Максимум сообщений пользователя за окно |
| `ANTISPAM_WINDOW_SECONDS` | `30` | Длина окна (секунды) |
| `ANTISPAM_TICKET_COOLDOWN_SECONDS` | `60` | Пауза между созданием обращений (секунды) |

При превышении лимита бот присылает предупреждение «🐢 Вы отправляете сообщения
слишком быстро» (не чаще одного раза за окно) и пропускает дальнейшие сообщения.
Счётчики хранятся в памяти процесса (`utils/throttle.py`) — при рестарте сбрасываются.

## Ограничения

- `Telegram API` ограничивает создание тем (в среднем ~10–20 в секунду) —
  для службы поддержки лимит практически не достигается.
- Если бот заблокирован пользователем, ответ администратору доставлен не будет
  (в теме появится предупреждение, а в лог запишется событие).
- Для очень высоких нагрузок рассмотрите переход на PostgreSQL
  (модуль `database/db.py` — единственное место, которое нужно заменить).
